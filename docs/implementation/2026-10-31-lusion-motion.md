# Lusion 动效探索与个人博客重建记录

## 结论

本次二次开发保留了原博客的 Vue 3、FastAPI、PostgreSQL 与后台内容能力，重建了公共展示层，并把大规模 WebGL 站点中可维护的动效思想抽取为独立层。`lusion.co-ddw/` 只用于本地研究，不进入构建产物，也不形成运行时依赖。

项目的职责边界是：

- DOM 负责文字、语义、导航、表单和可访问性。
- CSS 负责响应式布局、排版、轻量过渡和静态后备。
- Three.js 只绘制首页的装饰性几何体，不接管页面滚动，也不承载内容。
- 现有文章、标签、搜索、评论、认证、上传和后台接口继续由原系统提供。

## 从参考项目吸收的设计方法

本地参考展示了实验型站点常见的分层做法：资源分段准备，WebGL 与 DOM 屏幕坐标同步，输入采样和渲染循环分离，页面可见性控制生命周期，并用时间线组织动画。个人博客采用了其中适合长期维护的部分：

1. 动效资源和 Three.js 场景按需加载，避免阻塞首屏内容。
2. 指针坐标转换为场景局部 NDC，输入经过阻尼和边界约束。
3. 原生滚动保留给浏览器，视觉层只采样 `scrollY`。
4. 页面离开、画布离屏或标签页隐藏时停止渲染循环。
5. 减少动态效果时直接使用静态海报，不下载 Three.js 场景代码。
6. WebGL 不可用时捕获初始化失败，保留完整内容和 CSS 海报。

参考目录中的模型、音频、专有文案、原始着色器和设计资产没有被复制。当前页面采用原创的二十面体、顶点波形与界面文案。

## 已实现架构

```text
frontend/src/
├── data/portfolio.ts                 # 可编辑的个人信息、项目与资源
├── graphics/
│   ├── motion.ts                     # 阻尼、边界、指针坐标数学
│   ├── shaders.ts                    # 原创顶点和片元着色器
│   └── liquidScene.ts                # 懒加载的 Three.js 场景控制器
├── components/
│   ├── immersive/ImmersiveScene.vue  # 画布、海报、生命周期和降级
│   ├── immersive/ScrollReveal.vue    # 仅渐进增强的滚动揭示
│   ├── immersive/MagneticLink.vue    # 保持语义的轻微磁吸链接
│   ├── blog/ArticleRow.vue           # 公共文章条目
│   └── blog/StatePanel.vue           # 空、错误等页面状态
├── components/navigation/SiteHeader.vue
├── views/blog/                       # 首页、归档、搜索、标签、文章、关于
└── style.css                         # 站点视觉 token 与公共排版
```

`portfolio.ts` 是展示数据的唯一编辑入口。`profile` 控制名称、角色、介绍、地点和原则；`projects` 控制项目卡；`resources` 控制资源入口；`navigation` 控制主导航。文章内容继续来自数据库 API，不复制到前端数据文件。

## 视觉与交互

- 使用暖纸色、墨黑、酸橙绿与电蓝组成的原创视觉系统。
- 首页包含动态标记、近期写作、项目、工作原则与资源入口。
- 新增 `/writing` 归档页，支持真实分页、加载与错误状态。
- 搜索支持查询参数、分页与空结果；标签页与文章详情复用新排版。
- 导航支持桌面锚点、移动菜单、键盘 Escape 关闭、搜索入口和账户状态。
- 路由维护页面标题、前进后退恢复位置、跨页锚点偏移和页面顶部复位。
- 移动菜单图标完整包含在按钮边界内，站点在 390px 视口没有横向溢出。

## WebGL 实现边界

`liquidScene.ts` 当前只实现一个原创低多边形二十面体：使用时间和指针驱动顶点波，叠加 Fresnel 风格调色与线框层，设备像素比上限为 `1.75`，并限制每帧时间步长以保持动画稳定。

本次没有实现参考项目中更低层的 ping-pong 纹理模拟或后处理通道。继续扩展前，应先有明确的视觉目标、性能预算和浏览器测试，避免为了“完整移植”增加无法维护的 GPU 代码。

WebGL 不可用或开启减少动态效果时：

- `.scene-poster` 显示静态 CSS 视觉。
- Three.js 的动态模块不载入。
- 文章、导航、按钮和链接保持可操作。
- 场景离屏时停止 `requestAnimationFrame`；标签页隐藏时同样暂停。

## 后续扩展条件

如果以后需要得到参考项目级别的复杂视觉效果，可以增加独立的 GPU 场景模块和资源预算测试，但应保持以下契约：内容不依赖 WebGL；所有观察器、监听器、动画帧和 GPU 资源在卸载时释放；减少动态效果与上下文失败均有可见后备。先以真实需求决定何时引入 ping-pong 模拟、屏幕孔洞或更复杂的资源流。
