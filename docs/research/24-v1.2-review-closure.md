## 执行裁决及代价

以下汇总本计划台账的所有 `Ruling:`，使执行目录清理后仍可审查：

| 裁决 | 理由及潜在代价 |
| --- | --- |
| 沿用用户指定目录与 `codex/blog-v1.2` | 保留已有研究、修复和本地证据；分支不隔离同时写同目录的其他进程，本轮未发现其他写者 |
| 使用计划已有的 Python Playwright | 固定夹具及现有运行时可重复；没有把依赖安装进前端 lockfile，换机器需准备对应运行时 |
| 根 node_modules 与运行证据忽略 | 防止本地工具和生成物入库；复现脚本/原始输出在本机忽略目录，不由 Git 分发 |
| 404 矩阵是 2×2×2，等待最终 UI | 1200 ms 延迟下不能用 500 ms 定时截断；仍未覆盖任意延迟与超时组合 |
| 用可观察行为/网络测试代替源码字符串检查 | 测用户实际结果；依赖生产浏览器矩阵识别资源边界，不对 prose/ignore 规则添加机械测试 |
| 编译/浏览器用现有 Anaconda，pytest 用仓库 venv | 系统 Python 缺少相关依赖；命令须保留解释器选择，不能把系统环境失败算作产品失败 |
| 夹具 404/503 的资源错误单独保留和排除 | 预期失败是测试输入；非预期 page error 与其他网络错误仍应失败 |
| 初始焦点在 Tab 前采集 | 修复测量顺序；旧脚本记录不能当成初始焦点证据 |
| 按用户要求取消图片查看及截图证据 | 用 DOM、网络、焦点、滚动、帧、生命周期和非图片 trace；不能据此判定视觉完全无回归 |
| 真实生产 API、CDN、缓存和部署仍未覆盖 | 固定夹具不能代表服务器；没有据此执行发布或宣称生产性能 |
| Safari/Firefox、真实移动/低端硬件、后台功耗/GPU、context 恢复仍未覆盖 | 本机 Chromium 和合成 visibilitychange 只证明对应代码路径；设备与功耗收益未获证实 |
| VoiceOver、真实辅助技术和视觉效果仍未覆盖 | DOM/焦点检查不能代替实际感知体验；后续人工验收仍有价值 |
| 现有 Markdown 外部辅助依赖保持原样 | 它们不是本轮新增项；曾有一次真实网络连接关闭导致矩阵失败，保留失败，不把错误加入宽泛白名单，后续原协议重跑成功；代码/公式/图表扩展仍受外部可用性影响 |
| 必要的错误保护修复保留 | gzip 比 Task 5 更小，原始入口仍增加 12 B；这一修复不能冒称原始字节零增长，自适应画质没有新增公共入口模块 |

审查中“反馈错误替换”按实际用户影响重评为重要问题并已修复；没有数据破坏证据。截图事项服从用户指令，不视为待修的代码缺陷。没有遗留的审查代码问题或待处理 minor；未验证的平台和性能归因继续列为发布残余风险。
