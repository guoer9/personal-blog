# v1.2 发布验收

## 本轮范围

- 日期：2026-11-01（Asia/Shanghai）。
- 分支：`codex/blog-v1.2`。
- 验收对象：Tasks 1–7 的实现、研究证据和回归矩阵。

## 发布结论

**PASS WITH RESIDUAL RISK**

v1.2 的开发、整分支审查后的修复、功能矩阵和包体积门禁已完成。本地完整性能协议的 LCP 和首页 INP candidate 达标，但桌面首页仍有两条超过 `200 ms` 的长任务，未完成来源归因，因此性能子门禁未获无条件 PASS。真实生产环境与视觉效果的边界也仍保留。

初稿中的公共主 JS gzip `+1 B` 已在最后修复批次消除：三次构建都是 `60,288 B`，比 Task 5 的 `60,298 B` 少 `10 B`；原始入口体积增加的 `12 B` 单独记载。审查闭环和全部执行裁决见 [24-v1.2-review-closure.md](24-v1.2-review-closure.md)。本结论是本地开发验收，不表示已经合并或部署。

## 未验证项与接受风险

- 本地 Vite preview 和即时 API 固定夹具不能代表真实生产网络、后端延迟、CDN、缓存策略或服务器资源。
- 未在 Safari、Firefox、真实 iOS/Android 设备、低端 CPU/GPU 上复测。
- 未测量真实操作系统后台标签页的功耗、GPU 内存曲线或 WebGL context loss 后恢复。
- 未查看截图，因此没有给出完全的视觉无回归结论；视觉人工验收仍是发布前的独立动作。
- 性能数据中的 INP 是实验室交互候选值，不等同于真实用户 INP。
- 桌面首页超过 `200 ms` 的长任务仍需归因；不能仅凭最大值降低就声称不存在新增长任务。
- 公共入口原始体积比 Task 5 增加 `12 B`，gzip 则少 `10 B`；若发布政策要求所有原始字节也不增长，仍须单独处理这一必要修复的取舍。
- 既有 Markdown 辅助库有外部请求；本轮未新增或复制外部素材，一次连接关闭导致的验收失败已保留并在相同严格断言下重跑通过，尚未保证扩展语法的离线可用性。

## 回滚条件

- 公共主 JS gzip 超过 `230 kB`、全局 CSS gzip 超过 `20 kB`，或公共路线重新加载 Element Plus 资源。
- 登录、注册、后台菜单、上传、删除确认、退出登录任一功能失败。
- 自适应画质引入额外公共入口代码、出现单帧抖动、`liquidScene` 增长超过 `5%`，或 reduced-motion、离屏、隐藏、WebGL 失败、卸载路径回归；必要请求错误修复的 `+12 B` 作为独立裁决记录。
- 出现新的可访问性回归、横向溢出、后台空白或 WebGL 资源泄漏。
