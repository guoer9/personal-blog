# Lusion 动效探索与个人博客重建记录

## 结论

本次二次开发保留了原博客的 Vue 3、FastAPI、PostgreSQL 与后台内容能力，重建了公共展示层，并把大规模 WebGL 站点中可维护的动效思想抽取为独立层。`lusion.co-ddw/` 只用于本地研究，不进入构建产物，也不形成运行时依赖。

项目的职责边界是：

- DOM 负责文字、语义、导航、表单和可访问性。
- CSS 负责响应式布局、排版、轻量过渡和静态后备。
- Three.js 只绘制首页的装饰性几何体，不接管页面滚动，也不承载内容。
- 现有文章、标签、搜索、评论、认证、上传和后台接口继续由原系统提供。

## 从参考项目吸收的设计方法

本地参考展示了实验型站点常见的分层做法：资源分段准备，WebGL 与 DOM 屏幕坐标同步，输入采样和渲染循环分离，页面可见性控制生命周期，并用时间线组织动画。个人博客采用了其中适合长期维护的部分：

1. 动效资源和 Three.js 场景按需加载，避免阻塞首屏内容。
2. 指针坐标转换为场景局部 NDC，输入经过阻尼和边界约束。
3. 原生滚动保留给浏览器，视觉层只采样 `scrollY`。
4. 页面离开、画布离屏或标签页隐藏时停止渲染循环。
5. 减少动态效果时直接使用静态海报，不下载 Three.js 场景代码。
6. WebGL 不可用时捕获初始化失败，保留完整内容和 CSS 海报。
7. 用首页阅读顺序组织四阶段视觉叙事，动效跟随内容推进，而不抢占内容。

参考目录中的模型、音频、专有文案、原始着色器和设计资产没有被复制。当前页面采用原创的二十面体、顶点波形与界面文案。

## 视觉与交互

- 使用暖纸色、墨黑、酸橙绿与电蓝组成的原创视觉系统。
- 首页包含动态标记、近期写作、项目、工作原则与资源入口。
- 首页按 `idea → writing → projects → signal` 四阶段推进；WebGL 形体、尺度、旋转和情绪随整页阅读进度变化。
- 右侧叙事轨道显示阶段和总进度；小于 1680px 时保留 1px 进度线并收起文字，避免挤压正文。
- 磁性链接使用有阻尼的弹簧反馈；触控指针不触发位移动效，保留直接点击与键盘操作。
- 项目卡在精细指针下提供轻微倾斜、抬升、局部光场和箭头反馈；离开后弹簧回归，触控设备关闭倾斜。
- 场景提供手动暂停与恢复开关，标签使用动态 `aria-label` 和 `aria-pressed`，并将选择保存到 `localStorage['field-notes:motion-paused']`。
- 新增 `/writing` 归档页，支持真实分页、加载与错误状态。
- 搜索支持查询参数、分页与空结果；标签页与文章详情复用新排版。
- 导航支持桌面锚点、移动菜单、键盘 Escape 关闭、搜索入口和账户状态。
- 路由维护页面标题、前进后退恢复位置、跨页锚点偏移和页面顶部复位。
- 移动菜单图标完整包含在按钮边界内，站点在 390px 视口没有横向溢出。

## WebGL 实现边界

`liquidScene.ts` 实现一个原创低多边形二十面体：使用时间、指针和阅读进度驱动顶点波，叠加 Fresnel 风格、线框层和少量浮游粒子。桌面设备像素比上限为 `1.75`、粒子数为 `96`；窄屏或四核以下设备使用三级细分、`1.25` 像素比和 `54` 个粒子。输入经过与帧率无关的阻尼，并限制每帧时间步长以保持动画稳定。

动效的生命周期契约：

- `IntersectionObserver` 在画布离屏后停止 `requestAnimationFrame`，回到视口时恢复。
- `visibilitychange` 在标签页隐藏后停帧，不只依赖 CSS 隐藏。
- 减动设置优先于用户的手动播放选择；减动时主动释放 WebGL 控制器和 GPU 资源。
- WebGL 初始化或上下文失败时显示 CSS 海报，并继续允许正文阅读和键盘导航。
- 手动暂停后即使 WebGL 未初始化，界面也明确显示 `PAUSED / MANUAL` 静态后备。

本次没有实现参考项目中更低层的 ping-pong 纹理模拟或后处理通道。继续扩展前，应先有明确的视觉目标、性能预算和浏览器测试，避免为了“完整移植”增加无法维护的 GPU 代码。

WebGL 不可用或开启减少动态效果时：

- `.scene-poster` 显示静态 CSS 视觉。
- Three.js 的动态模块不载入。
- 文章、导航、按钮和链接保持可操作。
- 场景离屏时停止 `requestAnimationFrame`；标签页隐藏时同样暂停。

## 已知性能瓶颈与后续方向

当前构建已把 Three.js 场景拆成独立懒加载块，但公共应用仍全局注册 Element Plus，主包约 `1,067.64 kB`，gzip 约 `353.07 kB`；完整 Element Plus CSS 约 `355.64 kB`，gzip 约 `49.24 kB`。Vite 对主包和文章编辑包发出大于 `500 kB` 的警告。这是首页启动成本的下一处主要来源。

推荐的下一轮顺序：

1. 把 Element Plus 与中文语言包从公共首页拆出，只在认证、详情交互和后台路由注册；逐页验证登录、标签、文件、文章编辑、评论删除与消息提示。
2. 结合真实网络限速记录 LCP、INP 和首屏 JS 传输量，再确定主包优化优先级。
3. 在支持触摸且具备精细指针的混合设备上验证卡片倾斜，用 `(hover: hover) and (pointer: fine)` 进一步收敛能力判断。
4. 若继续深化视觉，可把 WebGL 输入、质量和场景状态抽成独立控制器测试，并加入 GPU 上下文丢失恢复；现阶段无需引入 ping-pong 模拟或重量级后处理。

## 后续扩展条件

如果以后需要得到参考项目级别的复杂视觉效果，可以增加独立的 GPU 场景模块和资源预算测试，但应保持以下契约：内容不依赖 WebGL；所有观察器、监听器、动画帧和 GPU 资源在卸载时释放；减少动态效果与上下文失败均有可见后备。先以真实需求决定何时引入 ping-pong 模拟、屏幕孔洞或更复杂的资源流。
