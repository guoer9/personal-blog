# Lusion DDW 逆向研究计划

> 本文是研究工作流与门禁，不是“研究目标”或 token budget。研究以本地证据为准，按阶段推进；每一阶段结束都必须留下可复查记录。

## 时间与调度边界

- 调度窗口：约 10 小时，默认每 40 分钟检查一次。
- 单轮工作：约 30–35 分钟，只推进当前门禁允许的一个可验证子任务。
- 主通道：`launchd` 托管的 30 秒本地循环；辅助通道：独立的 40 分钟 `launchd` 定时器。两者共用运行锁和队列去重检查。
- 调度器只向当前 Codex 会话排队续跑消息；会话忙碌或已有待执行消息时跳过，避免并发写作和重复排队。
- 状态检查：`python3 scripts/research/night_research_scheduler.py status`；诊断：`diagnose`。
- 到截止时间自动卸载；也可用 `output/research-scheduler/STOP` 或 `python3 scripts/research/night_research_scheduler.py stop` 停止。
- 运行依赖 Mac 保持登录、Codex 应用可接收队列消息、网络可用。`caffeinate` 只能延缓空闲睡眠，不能保证合盖睡眠时继续执行，这不是调度器能可靠绕过的条件。
- 日志与运行状态在 `output/research-scheduler/`，不纳入版本控制；研究证据仍必须写入 `docs/research/`。

## 不在范围内

- 不复制 Lusion 的素材、着色器、模型、音频或文案。
- 不把参考站点的 README、反编译摘要或静态截图直接当成已验证事实。
- 不在没有视觉目标、性能预算和复测的情况下移植复杂后处理、ping-pong 模拟或大型 GPU 管线。
- 不用未测得的数字填满报告；无法验证时明确标记“待复测”。

## 阶段与门禁

### 阶段 0：基线与研究纪律

产出：现有站点体验基线、工具可用性、测量口径和已知缺口。

进入下一阶段的门禁：

- 记录视口、设备缩放、浏览器版本、网络条件、是否启用减少动态效果。
- 区分“已有结论”“本轮重测”“待复测”，不混写。
- 对桌面、移动端、键盘路径和加载性能至少各有一条可复查证据；不能运行时记录原因。
- 建立 `docs/research/` 下的阶段记录，格式见下文。

### 阶段 1：现有站点体验审计

产出：逐页体验审计与问题清单，覆盖首页、归档、搜索、文章、关于和错误状态。

检查维度：

- 首屏层级、可读性、信息密度、导航可理解性。
- 桌面与移动布局、横向溢出、触控与精细指针差异。
- 键盘焦点、跳转、菜单关闭、状态提示和减少动态效果。
- 主包、懒加载块、字体/图片资源、首屏 JS 传输量。
- 滚动、动画、WebGL 离屏和页面可见性生命周期。
- 通过真实浏览器复测已有性能数字；未复测的旧数字标为“历史证据”。

进入下一阶段的门禁：

- 每个公共页面至少有一个桌面证据和一个移动证据，或明确写出无法采集的原因。
- 关键交互有成功与失败路径；重要缺陷有稳定复现条件。
- 性能结论写明工具、样本数、视口、网络和测量时间。

### 阶段 2：DDW 结构拆解

产出：页面章节、滚动映射、输入反馈、DOM/WebGL 同步、资源与生命周期图。

工作顺序：

1. 仅根据可执行代码和浏览器行为建立页面—章节—滚动区间映射。
2. 追踪输入采样到视觉状态的路径，区分原生滚动、虚拟滚动和渲染循环。
3. 查找 DOM 代理与 WebGL 坐标同步的接口和更新顺序。
4. 追踪场景、纹理、几何体、监听器、观察器与动画帧的创建和释放。
5. 把 README 中的架构说明逐项标为“代码已证实”“行为已证实”“仅文档声称”“未验证”。

进入下一阶段的门禁：

- 每条结构结论至少指向一个本地代码位置或浏览器复测结果。
- 文档声称与代码事实分开记录。
- 至少完成一条从输入到画面的调用链和一条资源释放链；未能完成的缺口写清下一轮最小验证。

### 阶段 3：可迁移机制筛选

产出：机制候选表，按“用户体验收益、实现成本、性能风险、可访问性风险、与本站兼容性”排序。

候选必须满足：

- 能用本站原创素材和代码重写，不依赖参考站点的专有资源。
- 有可测量的假设和失败判据。
- 优先原生滚动、渐进增强、生命周期正确和可降级方案。
- 不为追求视觉相似度牺牲内容可读性、键盘访问或首屏性能。

进入下一阶段的门禁：

- 每个候选都有“保留 / 延后 / 放弃”的判断和证据。
- 至少有一个低风险候选和一个高风险候选被对比。
- 选定实验的预算包含包体积、帧时间、首屏和可访问性回归指标。

### 阶段 4：原创实现实验

产出：小范围、可回滚的实现实验和对照测量。

实验要求：

- 先写假设、变更范围和停止条件，再改代码。
- 使用本站原创视觉与文案；参考目录只作为机制研究材料。
- 一次只验证一个主要变量，保留基线数据。
- 同时检查桌面、移动、减少动态效果、键盘和 WebGL 不可用路径。
- 失败的实验也要保留记录和移除理由。

进入交付门禁：

- 单元测试、构建和仓库基线检查通过。
- 有前后对照数据，且复测不只跑一次。
- 无横向溢出、明显焦点陷阱或无内容可读性回归。
- 资源正确释放，页面离屏或标签页隐藏后停止无意义绘制。

## 每阶段记录格式

文件名使用 `NN-主题.md`，例如 `01-baseline-audit.md`、`02-ddw-structure.md`。每次记录必须包含：

```markdown
# 阶段标题

## 本轮范围
- 日期、视口、浏览器、网络、相关提交或文件。

## 证据
- 事实、来源路径/行号、命令或浏览器观察；明确证据等级。

## 实验
- 假设、变更、变量、成功/失败判据。

## 复测结果
- 与基线对照的原始数据和结论；未复测项明确标注。

## 下一步假设
- 下一轮唯一优先验证点，以及阻塞条件。
```

证据等级统一使用：

- `E1`：本轮真实浏览器或可重复脚本测量。
- `E2`：本地源码/反编译代码直接定位。
- `E3`：历史记录或截图，尚未本轮复测。
- `E4`：README、二手说明或推测，尚未证实。

## 每轮停止条件

满足任一条件即停止本轮并写入记录：

- 完成一个可验证子任务，并产生证据与复测结果。
- 达到约 35 分钟且可以安全中断。
- 遇到需要人工判断的视觉或产品决策。
- 测量工具不可用，且已记录失败输出和可替代路径。
- 继续执行会引入未授权素材、显著性能风险或不可回滚改动。

## 调度器操作

```bash
# 状态
python3 scripts/research/night_research_scheduler.py status

# 安装并启动 10 小时窗口
python3 scripts/research/night_research_scheduler.py start \
  --thread 01a192ff-9852-7122-8b39-d31fb1cee288 \
  --duration-hours 10 \
  --interval-minutes 40

# 主动停止
python3 scripts/research/night_research_scheduler.py stop
```

运行状态与日志位于 `output/research-scheduler/`，不纳入 Git。
