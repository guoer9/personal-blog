## 3. 当前问题：事实与设计判断

### 3.1 首页的内容顺序承载了旧定位

事实：首页依次为主视觉/签名、最新文章、代码项目、影像与音乐、工作原则、资源入口。作品页主标题为 “Code. Film. And a little music.”。

依据：`frontend/src/views/blog/Home.vue:303`、`:347`、`:390`、`:395`、`:413`；`frontend/src/views/blog/Works.vue:64`。

判断：签名完成后，体验立刻转向阅读和技术作品目录；这会打断视觉表演，也使音乐成为附属兴趣。“And a little music” 更直接削弱音乐人身份。

建议：主体验优先展示声音、影像和交互；文字文章放到后段/归档。技术项目仍可访问，但不靠项目说明承担首页的技术展示。

### 3.2 首屏素材没有建立本人的视觉身份

事实：当前主视觉为大理石雕塑演示肖像，并标注“人物习作 / 非本人照片”；配置为 `isDemo: true`。About 仍使用几何 G/ 图形代替人物素材。

依据：`frontend/src/graphics/scenes/home/portraitAssets.ts:28`，`frontend/src/components/immersive/ImmersiveScene.vue:39`，`frontend/src/views/blog/About.vue:124`。

判断：雕塑、玻璃球、复古衬线字、荧光色、Vlog 截图分别有表现力，但尚未形成与陈果/音乐明确相连的美术设定。当前雕塑占据最大面积，却无法帮助观众记住本人。

建议：优先确立主视觉素材的艺术方向。候选是真实音乐人影像、演奏细节或由真实音乐生成的抽象形态；素材不足时先使用现有球体与手写签名建立个人标识。真实肖像需要用户选定素材，不能把演示雕塑当作本人。

### 3.3 球体和页面排版各自成立，合在一起缺少空间分工

事实：球体已居中；文章、卡片与章节文字仍按传统网页的全宽/网格排版跨过中心。截图可见正文、作品说明与球体轮廓叠在一起。

依据：`home-writing.png`、`home-projects.png`、`home-media.png`。

判断：继续调整滚动插值不能独立解决构图冲突。需要围绕球体安排前景、后景、图片入口和文字位置。

建议：保持球体基础大小和中心位置，让作品画面在外围、前后层和视口边缘交接。每个阶段有一个主视觉焦点；少量名称贴近对应对象，长文留到阅读页面。手机端单独编排上下出入和短标签，不把桌面两栏机械压窄。

### 3.4 首屏与内页的视觉完成度差距大

事实：首页有肖像揭示、流体/玻璃与签名；Works 内页以标题、筛选条、两列卡片为主。其他页的 WebGL 多为低透明度方块、线条和圆环；页面 DOM 转场是 180ms 淡入淡出。

依据：`frontend/src/graphics/scenes/works/WorksScene.ts:14`，`frontend/src/layouts/MainLayout.vue:236`，`navigation-reading.jpg`。

判断：独立几何装饰与内容没有足够强的对应关系，从首页进入内页时容易感到回到另一套模板。

建议：优先统一首页→音乐展廊→单曲舞台的视觉关系。点击的封面、标题或签名线条成为转场中的连续对象，返回时恢复对应作品位置。归档也继承字体、颜色、线条和入场语言。

### 3.5 音乐体验已有基础，但音乐还没有驱动画面

事实：公开 API 目前包含两首音乐《我也想辍学》《凌晨的雨》，均有音频、视频和封面；另有两条影像作品、四个代码项目。音乐详情使用原生音频控件，标题在页头和播放器内重复。音乐场景根据 `playing` 对整体轻微旋转，使用 `playbackProgress` 显示进度；柱形高度是预设值。

依据：`evidence.json`；`frontend/src/components/works/WorkPlayer.vue:47`；`frontend/src/graphics/scenes/work-detail/WorkDetailScene.ts:84`。

判断：已有真实声音和播放状态可复用，当前视觉仍偏“播放器旁放一个装饰频谱”。

建议：候选核心交互为真实音频分析驱动球面细节、光线及签名线条。低频可映射表面起伏，中高频映射高光/细线；保持球体基础尺寸和中心稳定。交互以明确的播放操作启动，静音浏览也保留完整视觉表达。不要把定时正弦动画称为真实节奏分析。

### 3.6 作品封面和编排比继续叠特效更需要设计

事实：代码卡片使用 ▦、∿、✳ 等符号；媒体封面带有视频字幕、黑边和不同构图。所有内容主要使用同规格矩形卡片，首页音乐与影像共用一组两列卡片。

依据：`frontend/src/views/blog/Home.vue:369`，`frontend/src/components/works/WorkCard.vue:9`，`current-pages.jpg`。

判断：素材品质、裁切和比例没有统一，动效会把这种不一致一起放大。

建议：为两首音乐先建立统一封面/动态封面艺术方向；主作品使用大画幅，次级作品形成节奏变化。两首歌适合一主一次的舞台或双作品构图，不需要照搬参考的四列大量收藏墙。

### 3.7 菜单具备空间，但缺少视觉内容

事实：首页菜单展开后为文本横线、Works/About、巨大 Contact 条和大量空白；内页桌面改成另一套顶部导航。

依据：`frontend/src/components/navigation/SiteHeader.vue:129`、`:169`；`current-menu.png`。

判断：菜单是最容易展示高级交互、同时改善方向感的位置。目前它更多是功能目录。

建议：将音乐、影像、关于作为视觉入口，悬停/键盘聚焦时展示对应真实封面或片段；移动端用点击选择明确呈现。档案、搜索、账户、传输等工具归入次级入口。联系作为清楚的文字入口即可，不必占满菜单主视觉区域。名称、选中状态和关闭方式应在首页/内页一致。

### 3.8 文章入口的语义存在重复

事实：本次 `/posts` 与 `/documents` 返回相同两篇公开内容；从 Writing 点击文章进入 Documents 路由，阅读页固定显示“公开资料 / 返回资料库”。分类输入还要求访客填写精确分类名。

依据：`evidence.json`，`frontend/src/views/blog/DocumentDetail.vue:109`，`frontend/src/views/blog/Documents.vue:75`。

判断：从用户视角难以理解“文章”和“资料库”的区别。首页的搜索、归档、资料库、资源卡片形成重复入口。

建议：前台收敛为一个“档案”入口，内部再区分文章、创作记录、技术笔记。沿用现有数据来源与链接兼容，不需要先重写后端。详情保留来路和筛选状态，避免读完被送进另一种目录。

### 3.9 字体、色彩、符号需要成为同一套美术语言

事实：内页普遍采用超大英文衬线标题、蓝色斜体、等宽元信息、细边框和圆形箭头；中文正文与英文标题的尺度相差很大。移动音乐分类首先消耗大量空间展示总标题，才出现音乐。

依据：`frontend/src/style.css:12`，`frontend/src/components/blog/ArticleRow.vue:70`，`mobile-pages.jpg`。

判断：大标题、色块和线框的使用方法重复，但没有根据场景角色分出重点。访客先看到模板语言，再看到作品。

建议：统一曲名/章节标题的排版语法，减少首页解释性段落；让大字参与构图。保留酸绿等可识别元素时，为其规定角色，例如签名/可交互焦点；蓝色由作品画面或球体材质承接，避免每个模块独立抢色。最终字体与色板应结合主视觉稿选择。

### 3.10 About 和站点说明也需要随定位调整

事实：About 的实践方向是 Systems、Intelligence、Interface；有大段维护性/AI 工程文案，还保留“减少动态效果提供静态后备”的旧描述。HTML meta description 仍定位为软件系统、AI 工程与技术写作。

依据：`frontend/src/views/blog/About.vue:49`、`:193`；`frontend/index.html`。

建议：将人物经历、创作影像和音乐放在前面，技术背景与站点实现说明收在后段。修正文案与实际动态策略的矛盾。优先级低于主体验，避免先花时间扩写新文案。

## 5. 可讨论的两条方向

### 声音剧场（建议优先）

将整个网站视为音乐人的可交互舞台。球体是持续居中的核心，陈果签名是空间中的线索，真实声音驱动球面细节与光线；作品封面与影像围绕中央构图进入，文字只提供曲名、身份和必要的操作提示。

候选顺序：个人主视觉 → 手写签名 → 第一首歌的视听场景 → 音乐/影像展廊 → 人物片段与联系 → 档案入口。

优势：音乐身份和前端技术在同一次体验中成立，既有球体和签名可以继续发展。代价：对音画映射、封面美术、移动构图和性能节奏的要求高，必须先把一个场景做透。

### 个人影像展厅

以全幅影像、音乐封面和人物摄影推动浏览；球体和签名作为贯穿其间的互动装置。采用更明显的画幅变化、遮罩、深度视差、图片交接和展览式菜单。

优势：在静音情况下就能充分表达气质，最容易从现有影像展开；接近参考源码重视人物和实物素材的编排方法。代价：依赖优质、统一的素材，声音与交互可能弱于“声音剧场”。

这两项是候选，不是用户已经批准的设计。建议以声音剧场为主，再借用影像展厅的素材构图方式。不要先加入新的独立“实验室”栏目来稀释音乐人的主体。

## 6. 建议的收敛次序

1. 确定主方向与主视觉素材：本人影像/演奏画面/抽象声音形态如何分工。
2. 先做一段可审美验证的完整体验：首屏 → 签名 → 一首歌。桌面和手机同时验证。
3. 再把音乐展廊、全屏菜单、进入作品/返回作品的连续关系设计完整。
4. 重排首页后半段，整理归档/工具入口及 About 的定位。
5. 最后完善其他页面的细节；不要同时重写所有路由、后端与动效系统。

验收应包含：不读长文也能知道这是音乐人的个人空间；音乐操作有明确可感知的音画反馈；球体保持原有基础尺寸和中心；跨区/切页有视觉对象连续性；桌面、触摸、键盘都能找到下一步；文字与工具退后但仍可查找。美术方向需要实画面确认，单元测试通过不能替代审美验收。
