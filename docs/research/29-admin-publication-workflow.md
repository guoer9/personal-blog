# 后台写入作品卡片：研究、接口和执行门禁

## 最新用户要求

2026-11-01：新增卡片必须从 admin 写入，完善后台并接入新作品功能；先写入开发流程，深入研究后再执行。云开发和 AI 页面暂停，只做本地模板。本文在作品发布业务实现前建立流程和验证标准。

## 研究证据

1. **现有后台可以复用身份，不能直接复用文章业务**（E2）。`backend/app/api/deps.py` 已实现 active user 与 administrator 校验；`posts.py` 接受 is_published，但管理员访问公开文章路由也可看到草稿。作品新接口必须将管理视图和公众视图分开，公众接口即使携带管理员凭证也只读已发布版本。
2. **直接把卡片数组写死不能满足维护要求**（E2）。本轮先做的 `frontend/src/data/works.ts` 是界面样稿与首批内容来源，最终读取必须改为 API。不能在 API 失败时静默回退样稿，否则后台下架的作品会重新出现。
3. **草稿和发布不是一个布尔值就够了**（设计推导）。用户编辑已发布作品时，不应每次保存就修改公众版本。采用一条作品记录中的 draft 与 published 快照；保存只改变 draft，明确“发布更新”才替换 published。下架清空 published，但保留草稿和文件。
4. **DDW 能支持展示机制，无法证明管理流程**（E2）。源码 `ProjectItemList`（34114起）从 DOM 的 data-id 建立项目列表，`ProjectItem`（33875起）按项目 ID 定位素材。没有获得原站 CMS/后台源码，不能推断其后台架构，更不复制运行时代码。本站建立自己的管理 API。
5. **文件与发布内容分离**（E2＋设计）。私有文件库以随机 ID 存原件；当前的公开 uploads 已被文章使用，直接收紧会破坏既有内容。新作品素材从私有文件库明确选择并生成独立发布副本，原件的下载、回收、重命名不应改变公开版本。
6. **响应过滤与媒体处理依据**（本轮官方文档查询）。Context7 `/websites/fastapi_tiangolo`，官方 response-model 文档明确输出 schema 能过滤私有字段；BackgroundTasks 文档说明重计算适合独立任务系统。本地 Starlette FileResponse 源码也包含 Range 支持。首版使用明确的输出 schema、可重建本地衍生文件，不把长时间视频转码塞到保存表单的请求里。

## 完整使用流程

1. 管理员登录 → “私有文件库”创建文件夹/上传素材；默认私有，分片续传后完整校验入库。
2. “作品管理” → 新建代码/影像/音乐作品。填写标题、唯一英文短链、简介、标签、说明、精选与排序。代码作品填写 GitHub 地址。
3. 从私有文件库选择封面、视频或音频，执行“准备发布素材”。系统核实格式并创建独立副本；MOV 原件拒绝直接发布，明确提示先生成网页播放版本。当前已有四份素材可用 `scripts/media/export_works.py` 重建播放文件和封面。
4. 保存草稿。草稿在公开列表、公开详情、公开素材 URL 中都不可见。后台预览使用管理员权限，原生播放器按需加载。
5. 预览确认后按“发布”。服务端校验必需字段、角色对应、文件真实存在且可播放，形成公开快照；前台下一次读取显示新卡片。
6. 修改已发布内容 → 保存草稿 → 公开版本维持 → “发布更新”替换快照。
7. “下架”隐藏作品；不再被任何公开作品引用的素材也不能继续通过公共接口读取。下架与私有原件删除互不替代。

## 接口与数据边界

- `GET /api/v1/works`：只读公开快照，支持 category、featured；返回 `{items}`。空集合是真实空状态，失败有重试。
- `GET /api/v1/works/{slug}`：只读已发布快照，草稿/下架返回404，不含绝对路径、原件 ID、管理员字段。
- `GET/POST /api/v1/admin/works`：管理员列表、新建草稿。
- `GET/PUT /api/v1/admin/works/{id}`：管理员读取、保存草稿，使用 version 防止多标签页覆盖；已占用 slug 返回409。shortlink 创建后固定。
- `POST /api/v1/admin/works/{id}/publish`：校验 version 和素材后发布快照；`POST .../unpublish`：下架并保留草稿。
- `POST /api/v1/admin/work-assets`：`{entry_id, role:'cover'|'video'|'audio'}`，从明确选择的私有条目准备发布副本。允许 JPEG/PNG/WebP、H.264/AAC MP4、AAC/MPEG音频，拒绝任意外部 URL、HTML/SVG、原 MOV。
- `POST /api/v1/admin/work-assets/preview-session`：仅管理员创建短时 HttpOnly/SameSite 预览 Cookie，限定媒体路径，避免把管理员 bearer 放进 video URL，也不先下载整部视频生成 blob。
- `GET /api/v1/admin/work-assets/{id}`：受限预览，支持原生 Range；`GET /api/v1/work-assets/{id}`：只有被公开快照引用时才能访问。私有磁盘路径从不静态挂载。

记录结构：作品 UUID、固定 slug、draft JSON、published JSON、version、创建/修改/发布时间；发布素材 UUID、来源私有条目 ID、角色、内部文件名、MIME、大小、时长。素材复制失败先清理临时文件，完整准备成功才可被选择。快照引用 asset ID，前端 URL 由 API 派生。

## 首版边界与选型

- 继续 Vue/FastAPI/PostgreSQL；新增独立作品管理表单，不引入 Strapi/Directus 第二套账号。
- 首批八件内容由可重复导入脚本**调用相同管理员 API**创建草稿、选择素材、明确发布；不在应用启动时自动写数据库，不以静态数组作为公开后备。
- 先实现本地兼容格式素材发布；耗时的 MOV→MP4 转码在本地导出工具运行，有失败记录、原文件不修改。后台异步转码队列、字幕、多清晰度、CDN/OSS、分享链接和远端部署待后续独立研究，不伪装成现有能力。
- 后台预览仅用于本人验收；首版发布说明不能声称受撤回保护的浏览器缓存可被强制抹除，公共媒体使用 no-store 防止新增缓存。

## 复测结果

本文件建立时发布业务尚未实现，目录与播放器4项样稿测试仅证明展示行为。随后按上述门禁实现并集成。2026-11-01最终固定构建浏览器闭环已通过，7次axe检查零违规；前端94项通过，作品与私有库SQLite＋真实PostgreSQL专项90项通过、1项跳过。媒体导出证据为 `output/research-profile/derived-media.json`；所有最终证据和限制集中记录在30号文档。

## 集成复测发现与修复决策（2026-11-01）

- 创建成功后立即保存预览，首次 PUT 返回404；稍后同ID GET/PUT成功。补ASGI发送边界测试，作品写操作须在成功响应前完成提交。
- 审查确认：发布目录不得与静态附件目录重叠；配置启动即拒绝。
- 完成入库已提交但响应被取消时，取消返回409；前端须通过幂等完成接口取回已存在条目并解除旧续传记录，普通网络失败仍保留记录。
- 准备副本增加总容量限制。首版本地采用共享POSIX锁，串行执行容量核对、复制和提交；临时文件和未引用副本均计入发布容量。作品引用写入和过期清理使用同一锁，避免清理与发布竞态。增加管理员清理入口，只回收超过24小时且不被草稿/公开快照引用的副本和遗留临时文件，原件不受影响。
- 次要建议暂缓：文件库界面分开展示待上传预占量；后端现有预占校验继续保留。
