# 阶段 1 续：搜索失败状态语义、焦点与重试恢复

日期：2026-11-01（Asia/Shanghai）

## 本轮范围

本轮仍处于阶段 1“现有站点体验审计”，只验证第 5 轮留下的唯一优先假设：搜索接口失败时，错误状态是否具有稳定可识别的语义与焦点落点，并能在重试成功后把用户带回结果上下文，同时不改变搜索输入和布局。

覆盖范围：

- 桌面视口 `1280 × 720`。
- 移动视口 `390 × 844`。
- Playwright CLI 驱动的 Chromium。
- 正常动效与 `prefers-reduced-motion: reduce`。
- 本地 Vite 开发服务器，`http://127.0.0.1:5173/`。
- 通过页面级网络拦截模拟搜索接口 `503`，并在重试阶段返回结构完整的成功响应。

本轮不进入 DDW 结构拆解，不移植参考站点的素材、着色器、模型、音频或文案。

## 证据

### E1：真实浏览器与本轮复测

原始输出：`output/playwright/baseline-audit-20261101/browser-search-error-focus-round6.txt`。

**第 5 轮结论补测（E1）：** 带查询首次进入 `/search?q=retest` 后，活动元素为 `SECTION.search-results`，结果区保持 `role="status"`、`tabindex="-1"`，焦点修复未回退。由于本地后端未运行，本轮补测该 URL 显示的是失败状态，而非第 5 轮的空结果状态；焦点与语义仍可比较。

**修复前失败态基线（E1）：**

- 结果区获得焦点，但错误容器没有 `role`，也没有标题。
- 摘要显示 `0 RESULTS`，会把请求失败误导为“成功但无结果”。
- 错误文案为“搜索暂时不可用，请稍后再试。重试 ↗”。
- 下一次 Tab 可以到达重试按钮；横向溢出为 `0`。

原始基线：`output/playwright/baseline-audit-20261101/browser-search-error-focus.txt`（本轮前半部分）。

**修复后失败态桌面复测（E1）：**

连续 3 次访问不同失败查询，3/3 均满足：

- 活动元素为 `SECTION.search-results`。
- 结果区具有 `role="status"` 和 `tabindex="-1"`。
- 错误区具有 `role="alert"` 和可见标题“搜索暂时不可用”。
- 摘要为 `SEARCH UNAVAILABLE`，不再显示 `0 RESULTS`。
- 重试按钮文案为“重试 ↗”。
- 横向溢出为 `0`；结果区宽度为 `1216 px`。

**重试成功恢复（E1）：**

确定性双阶段响应中，第 1 次搜索请求返回 `503`，第 2 次返回带完整分页字段的空结果。重试前焦点在“重试”按钮且错误状态可见；重试后：

- 错误区消失。
- 摘要恢复为 `0 RESULTS`。
- 活动元素回到 `SECTION.search-results`。
- 结果区保留 `role="status"`、`tabindex="-1"`。
- 页面级网络拦截累计处理 4 次 search 请求：前 3 次失败请求，以及重试触发的第 4 次成功请求。
- 横向溢出为 `0`。

**移动端与减少动态效果（E1）：**

- `390 × 844` 正常动效：错误区语义与标题正确，结果区获得焦点，宽度约 `354 px`，横向溢出为 `0`。
- `390 × 844` 且 `prefers-reduced-motion: reduce`：错误区语义、焦点与摘要不回退，横向溢出为 `0`。
- 未在真实触控设备、生产服务器或读屏软件组合下复测。

**工具边界：**

首次尝试用 CLI 的 `route` 替换同一 URL 的响应时，浏览器仍收到后端 `500`；随后在页面级路由中使用状态与请求计数才得到确定结果。第一次双阶段成功响应漏写 `page`、`page_size`、`total_pages` 等字段，导致失败态未解除，因此没有把它计作成功复测；补齐响应结构后重新执行并通过。该工具行为已与产品行为分开记录。

## 实验

**假设：** 明确区分失败与空结果，并为错误区提供可识别语义；在重试请求完成且焦点意图存在时，把焦点恢复到结果状态区，可以让键盘与读屏用户知道失败原因，并在恢复后继续浏览结果，同时不改变搜索输入和布局。

**变更范围：**

- `frontend/src/views/blog/Search.vue`：失败摘要、错误语义与重试焦点恢复。
- `frontend/src/views/blog/Search.test.ts`：失败语义和失败后重试恢复的回归测试。

**成功判据：**

- 失败时摘要不再显示 `0 RESULTS`。
- 错误区具有 `role="alert"` 和非空标题。
- 失败状态焦点落在结果区；键盘可以到达重试按钮。
- 连续 3 次失败表现一致。
- 重试成功后错误消失、摘要恢复，焦点回到结果区。
- 移动端和 reduced-motion 横向溢出为 `0`，内容与焦点不回退。
- 全量测试、构建和 `git diff --check` 通过。

**停止条件：** 出现错误状态不可见、焦点落点错误、重试无法恢复、横向溢出、reduced-motion 内容回退或构建失败时停止并记录；不扩展为全站错误处理、请求统一封装或读屏播报策略。

## 下一步假设

**下一轮唯一优先假设：** 搜索失败时，`role="status"` 的结果区包含 `role="alert"` 错误区，且显式聚焦结果区；这种组合可能让读屏软件重复播报，或在失败后无法清晰读出错误标题与重试动作。下一轮应在可用的真实读屏软件或可复现的无障碍树检查路径中，只验证一次失败播报与一次重试恢复的语义顺序；若工具不可用，则记录阻塞证据和替代方案，不扩展到全站错误处理。
